\begin{abstract}
\noindent Agentic search systems now approach the ceiling of open-web text benchmarks, yet on social media
they often fail before any reasoning starts: the link to a public post returns a verification page, a login
wall or an expired share token, and when the post is served, the answer often sits in speech, burned-in text,
carousel images or comments that a text pipeline never reads. Benchmarks that supply a fixed corpus,
pre-extracted media or the video itself cannot observe these failures. We present ReadProof, an open-source
harness and benchmark that make the read itself measurable. The harness enforces its access rules in code,
each pinned by a test: a declared identity, no cookies, no captcha solving or signature generation, and no
change of identity or address after a refusal. It evaluates robots.txt and Content-Signal on every request
under declared access profiles, returns a typed wall instead of page text, reads media through a platform's
official player, stores evidence as content-addressed records located by channel, and accepts a citation only
when its quote is an exact substring of a stored record. ReadProof-Bench has four tracks: access across the
link forms people actually paste, a planted-canary panel of the author's own posts with one code per channel,
questions answerable from exactly one channel of one post, and a counting pilot. With read--verify--count, a
training-free method that abstains with a typed cause, routes extraction by a priced budget and counts in
code, ReadProof serves \ResHeadCovReadProof{} of link forms under the user-initiated profile against
\ResHeadCovNaive{} for a naive fetch; baselines answer from \ResHeadAFWBaselines{} of the walls they receive;
and obeying robots.txt as a declared bot costs \ResHeadPenalty{} of coverage, which we call the honesty
penalty.
\end{abstract}

\section{Introduction}\label{sec:intro}

The headline benchmark for agentic search no longer separates systems. BrowseComp was built from questions
that are hard to find but easy to verify \citep{wei2025browsecomp}; its best reported accuracy is now 92.2\%,
from a system that runs four agents in parallel by default \citep{openai2026gpt56}, and an aggregator lists
no independently verified result among 77 self-reported ones \citep{llmstats2026browsecomp}. The
benchmarks that still separate systems have the shape of social media. Where evidence sits in web images
and video, the best reported accuracies are 24.25\% on MM-BrowseComp \citep{li2025mmbrowsecomp} and
36.0\% on MMSearch-Plus \citep{tao2025mmsearchplus}; where the answer requires exhaustive collection, the
best system completed 5\% of WideSearch tables when the benchmark was released \citep{wong2025widesearch}.

We argue that on social media, agents fail before they reason. A question about a post passes through six
stages (discover, acquire, detect, extract, ground, aggregate), and the first four come before any reasoning
about content. In the author's operational logs, a plain request to a Douyin or Toutiao share link returned
a 72{,}914-byte verification page with zero visible characters (Figure~\ref{fig:teaser}), and of nine link
forms of one public Xiaohongshu note (desktop and mobile URLs, share text and short links, with and without
the share token, on two domains) three opened while the rest ended at a 404 or a login page. These are
motivating observations, not results; Track~A re-measures them with the released harness. On the general
web, 20.9\% of the HTTP-200 responses that a static client receives lack the page's main content, and 13.1\%
of sites answer 200 for a path that does not exist \citep{zhang2026silent}. When a post is served, the
answer often lives in a channel a text pipeline does not read. On 252 real Xiaohongshu photo questions the
best of nine frontier vision-language models answers 52.8\% correctly, and agentic search adds 2.0
points \citep{jiang2026notevqa}; on open-web video, the authors of Video-BrowseComp find that ``the main
bottleneck lies before video understanding: agents often fail to find the answer-bearing video at all''
\citep{liang2025videobrowser}.

Existing benchmarks skip the read by construction. BrowseComp-Plus replaces the live web with a fixed
corpus so that comparisons are reproducible \citep{chen2025browsecompplus}; SoMe gives agents an offline
database of 9.2 million posts whose images and videos were converted to text by GPT-4o and Qwen2.5-VL
before evaluation \citep{xue2026some}; video deep-research benchmarks hand the agent the video
\citep{liu2026videodr,meng2026omnidr,liang2026groundedvdr}. Each choice is sound for its purpose, and each
removes acquisition, wall detection and extraction from what is measured. On a set of real links,
end-to-end accuracy decomposes as
\begin{equation}\label{eq:decomp}
  \mathrm{Acc} \;=\; c\,a_{s} \;+\; (1-c)\,a_{w},
\end{equation}
where $c$ is coverage, the share of links whose content the system actually received, $a_s$ its accuracy
on those links, and $a_w$ its accuracy on the rest. Published numbers report $a_s$. On questions that a
closed-book model cannot answer, an honest system has $a_w \approx 0$: after a wall, a correct answer means
the content came from somewhere other than the post, and an incorrect one is a fabrication.

Measuring acquisition without fixing the rules would reward circumvention. The widely used open-source
tools for Chinese platforms acquire content through logged-in browser sessions, stored login cookies and
reimplemented request signatures \citep{nanmicoder2026mediacrawler,xpzouying2026xhsmcp,evil0ctal2026douyinapi};
commercial assistants have surfaced content from publishers that block them
\citep{jazwinska2025tow,cloudflare2025perplexity}; and most agents prompted neutrally scrape sites whose
terms prohibit it, with compliance below 5\% \citep{imperial2026scrapebench}. We therefore measure reading
under declared access profiles whose rules are enforced in code, and we report what honesty costs. This
paper contributes:
\begin{itemize}[leftmargin=1.4em]
\item \textbf{ReadProof, an open-source harness} (Apache-2.0) in which access rules are data and tests, not
  prose. A policy gate decides every request under an access profile; a canonicalizer resolves share
  artefacts one gated hop at a time; readers prefer the platform's official player; a wall detector returns
  one of fourteen typed walls instead of page text; extractors write content-addressed records located by
  channel; a verifier accepts a quote only if it is an exact substring of a stored record; an append-only
  log records every decision; and agents reach all of it through the Model Context Protocol
  (Section~\ref{sec:harness}).
\item \textbf{ReadProof-Bench, a benchmark with four tracks.} Track~A scores access per link form on nine
  platforms. Track~K is a planted-canary panel: the author's own posts, each carrying a random code in
  exactly one channel, so that a correct code proves a read and a different code proves a fabrication.
  Track~B asks questions answerable from exactly one channel of one post, with gold from two independent
  extractors and closed-book and answerability filters. Track~C is a counting pilot
  (Section~\ref{sec:bench}).
\item \textbf{Read--verify--count, a training-free method} that abstains with a typed cause, routes
  extraction by a priced budget, gates citations on verified quotes with one re-ask, and counts in code with
  an adjusted classify-and-count estimator and bootstrap intervals (Section~\ref{sec:method}).
\item \textbf{A measurement of the honesty penalty}, the coverage that a declared, rule-following reader
  gives up when robots.txt binds it, reported with the effect of network origin, the rate of answers built
  on walls, quote validity, and cost per correct answer split into media extraction and model tokens
  (Sections~\ref{sec:setup}--\ref{sec:analysis}).
\end{itemize}
No single element is new: fetch failures \citep{zhang2026silent}, scraping compliance
\citep{imperial2026scrapebench}, social-media agents \citep{xue2026some} and Xiaohongshu question answering
\citep{jiang2026notevqa} each have recent precedents. The contribution is their combination: starting from
the share artefacts people paste for public posts, tracing every acquisition failure to a typed wall under a
declared profile that never works around platform defences, locating each answer's evidence in a labelled
channel with a verified quote, counting across posts against per-post gold, and pricing each correct answer.
Code, data and logs: \RepoURL.

\section{Related work}\label{sec:related}

\paragraph{Deep-research harnesses and context management.}
Recent technical reports isolate the harness by changing one component at a time. When a trajectory fills
80\% of the window, DeepSeek-V3.2 compares summarizing it with discarding tool history: discarding all
earlier tool calls raises BrowseComp accuracy from 51.4 to 67.6, while summarization reaches 60.2 after 364
steps on average \citep{deepseek2025v32}. Kimi~K2.5 (60.6 to 74.9, and 78.4 with a trained agent swarm;
\citealp{kimi2026k25}) and GLM-5.1 (68.0 to 79.3; \citealp{zai2026glm51}) report the same strategy,
DeepSeek-V4 keeps it for up to 500 steps in a 512K-token context \citep{deepseek2026v4}, and with a
one-million-token window Kimi~K3 gains 0.8 points from compaction (90.4 to 91.2; \citealp{moonshot2026kimik3}).
Other designs carry state outside the tool history: Tongyi DeepResearch rebuilds each step from an evolving
report \citep{tongyi2025deepresearch}, MiroThinker keeps the five most recent observations and adds local and
global verification of the evidence chain \citep{mirothinker2026h1}, AgentFold folds its history at several
scales \citep{ye2025agentfold}, and TTD-DR refines a draft report by retrieval-informed denoising
\citep{han2025ttddr}. In Anthropic's orchestrator--worker system, tokens spent explain 80\% of the variance on
BrowseComp, and sub-agents return condensed summaries of 1{,}000--2{,}000 tokens
\citep{anthropic2025multiagent,anthropic2025context}; blocking search results that named the benchmark, where
URL blocklists had failed, stopped agents from retrieving its answer key \citep{anthropic2026evalawareness}.
A controlled study finds that a central coordinator contains error amplification (4.4$\times$, against
17.2$\times$ for independent agents) and helps parallelizable tasks but hurts sequential ones
\citep{kim2025scaling}. DeepSeek has also released a plugin-based harness as a developer preview
\citep{deepseek2026harness,shi2026composability}. These systems share one reading interface, a search tool
plus a fetch or visit tool whose output a model summarizes; none types a refused read or locates evidence by
channel. ReadProof supplies that read path and exposes their context policies as a plug-in.

\paragraph{Reinforcement-learned search agents.}
Search-R1 trains with PPO or GRPO on an exact-match outcome reward, masking retrieved tokens from the loss,
against a 2018 Wikipedia index \citep{jin2025searchr1}; R1-Searcher rewards retrieval first and answers
second \citep{song2025r1searcher}; DeepResearcher trains against the live web \citep{zheng2025deepresearcher};
ZeroSearch replaces the search engine with a simulator model, cutting the cost of about 64{,}000 training
searches from \$586.7 through a commercial search API to \$17.7--70.8 of GPU time \citep{sun2025zerosearch};
ASearcher scales fully asynchronous RL to long horizons with about 16{,}000 H800 GPU-hours
\citep{gao2025asearcher}; WebSailor synthesizes high-uncertainty questions by obfuscating random-walk
subgraphs \citep{li2025websailor}. SocialBuddy, an RL search agent built for social content, searches
friends' feeds in a simulated environment of 10 million generated posts through structured filter tools,
trains with more than 2{,}000 H20 GPU-hours, and promises its code on acceptance \citep{li2026socialbuddy}.
Reliability studies temper these gains. During Search-R1 training, the share of correct Bamboogle answers
supported by retrieved evidence falls from 84.0\% to 42.9\% \citep{liu2026grounded}; eight paraphrased echoes
of a false claim overturn 58--73\% of previously correct answers, and exact-match RL drives abstention below
15\% once the evidence is deleted \citep{yang2026echospec}; and a replication obtained 0.403 where Search-R1
reports 0.431 \citep{xu2026howtotrain}. These environments are Wikipedia, the open web or a simulation, and
none of them meets a platform wall. ReadProof's deterministic signals (wall type, quote validity, count
error) could serve as verifiable rewards; we leave training to future work.

\paragraph{Benchmarks for agentic search.}
BrowseComp's 1{,}266 questions are built to be hard to find but easy to verify \citep{wei2025browsecomp};
BrowseComp-ZH carries the design to 289 multi-hop questions on the Chinese web \citep{zhou2025browsecompzh};
BrowseComp-Plus fixes a curated corpus of about 100{,}000 documents for 830 questions, on which GPT-5 rises
from 55.9\% to 70.1\% with a better retriever \citep{chen2025browsecompplus}; GAIA withholds the answers to
300 of its 466 questions for a leaderboard \citep{mialon2023gaia}; Humanity's Last Exam adds 2{,}500
questions \citep{phan2025hle}; and WideSearch asks for exhaustive tables \citep{wong2025widesearch}.
MM-BrowseComp \citep{li2025mmbrowsecomp} and MMSearch-Plus \citep{tao2025mmsearchplus} place evidence in web
images and video. VideoDR \citep{liu2026videodr}, OmniDR-Bench \citep{meng2026omnidr} and GroundedVDR
\citep{liang2026groundedvdr} start from a supplied video and add web search; in GroundedVDR the best of eight
systems answers 76.0\% correctly, yet none recovers the complete required web evidence for more than 8\% of
the questions. MultiVENT~2.0's 3{,}906 queries over more than 218{,}000 videos target visual content, audio,
embedded text and metadata \citep{kriz2025multivent}. Channel-specific text matters: OCR, speech and object-detection text
retrieved for a video improves long-video question answering \citep{luo2025videorag}, and Xiaohongshu's
multimodal note representations were redesigned because fine-tuned LLMs neglect image content
\citep{zhang2025notellm2}. On social media, SoMe is the closest agent benchmark:
9{,}164{,}284 posts behind an offline tool interface, media converted to text before evaluation, and
question answers scored by an LLM on a 0--5 scale \citep{xue2026some}. SNS-Bench evaluates LLMs on eight
social-networking-service tasks with 6{,}658 questions \citep{guo2025snsbench}. Xiaohongshu's own teams
release Qilin, an app-level multimodal retrieval dataset \citep{chen2025qilin}, NoteVQA
\citep{jiang2026notevqa} and VibeSearchBench, 200 proactive-search tasks on which the best F1 is 30.30
\citep{xhs2026vibesearchbench}; LocalSearchBench covers 900 local-life tasks over 1.3 million merchants
\citep{he2026localsearchbench}. None of these benchmarks starts from the share artefacts people paste for
public posts, and none scores whether the agent received the post at all.

\paragraph{Grounding and attribution.}
Attribution asks whether a generic reader would agree that a statement holds according to its source
\citep{rashkin2021ais}; ALCE scores citation recall and precision with an entailment model
\citep{gao2023alce}. An audit of four generative search engines found 51.5\% of generated sentences fully
supported by their citations and 74.5\% of citations supporting their sentence \citep{liu2023verifiability};
automatic attribution judges reach about 80\% macro-F1 \citep{li2024attributionbench}, and small checkers
approach much larger models at a fraction of the cost \citep{tang2024minicheck}. Audits of deployed systems
report citation accuracy of 40--80\% for deep-research configurations \citep{venkit2025deeptrace}; 3--13\%
of citation URLs that probably never existed \citep{rao2026reference}; most final-report errors originating
at the orchestrator rather than in retrieval \citep{hirsch2026blame}; syntheses that state claims more
strongly than their sources \citep{singharoy2026smoothing}; and users who prefer answers with more citations
even when the citations do not support the claims \citep{miroyan2026searcharena}. News audits found more than
60\% of source identifications wrong across eight AI search tools \citep{jazwinska2025tow}, and at least one
significant issue in 45\% of assistant answers across 22 public-service media organizations
\citep{ebu2025newsintegrity}. Verbatim quotation makes support checkable: GopherCite trains models to support
answers with quotes \citep{menick2022gophercite}, quote tuning aligns models to quote their pre-training data
\citep{zhang2025verifiable}, and R$^3$A, deployed in Xiaohongshu's search, extracts a verbatim evidence
fragment or none \citep{yuan2026r3a}. ReadProof's verifier is deterministic and adds what these checks lack on
social media: a channel and locator for every quote, and the hash of the snapshot it came from.

\paragraph{Fetch failures, walls and compliance.}
The closest measurement is general-purpose. Across 10{,}307 URLs, \citet{zhang2026silent} finds the 20.9\%
and 13.1\% rates quoted above and shows that text length, probe comparison and redirect-to-root together
recover 86\% of unusable responses at about 5\% false alarms; the study names no social platform and does
not test the answers built downstream. Solver services defeat challenge-based CAPTCHAs every time, and LLM
browser agents pass mainly when they carry an established account and browser state
\citep{ousat2026brokengates}, so ``not blocked'' is not evidence of permission; standardizing how failures
are handled moved one agent's reported web-task success from 87\% to 68.6\% \citep{akkil2026emergence}.
RFC~9309 scopes robots.txt to ``automatic clients known as crawlers'' \citep{rfc9309}; Content Signals
\citep{cloudflare2025contentsignals} and the IETF AIPREF drafts \citep{ietf2026aiprefvocab,ietf2026aiprefattach}
add usage preferences that are not yet standards. Measured compliance is selective: across 130 self-declared
bots, average robots.txt compliance was 0.42, and 0.307 for disallow-all rules \citep{kim2025scrapers}; within
one year, robots.txt came to restrict more than a quarter of the most actively maintained critical sources of
a major training corpus \citep{longpre2024consent}; a study of ten assistants with server logs and planted
codes found that page access and answer correctness diverge \citep{lopezfonseca2026robots}; Cloudflare reported
that Perplexity used undeclared crawlers to evade no-crawl directives \citep{cloudflare2025perplexity}; and
ScrapeBench finds compliance below 5\% for most agents on 1{,}626 sites that prohibit scraping, with 98.5\%
over-refusal by Claude Opus~4.6 on 269 sites that permit it, without measuring task utility
\citep{imperial2026scrapebench}. Operators document user-triggered fetchers as outside robots.txt: for
ChatGPT-User, ``robots.txt rules may not apply'' \citep{openai2026crawlers}, and Google-Agent ``generally
ignores robots.txt rules'' \citep{tollbit2026googleagent}. ReadProof pairs compliance with utility on social
platforms, and turns each refusal into a typed, logged data point.

\paragraph{Counting, aggregation and cost.}
No model exceeds 50\% on Oolong's long-context aggregation tasks at 128K tokens, where the bottleneck is
finding and adding up items rather than classifying them \citep{bertsch2025oolong}; WebAggregator finds
current agents retrieval-heavy but reasoning-light and builds aggregation-centred training data
\citep{wang2025webaggregator}. Quantitative opinion summarization counts how many comments support each key
point: Key Point Analysis ranks key points by prevalence \citep{friedman2021kpa,tang2024pakpa}, and QQSUM
reports count errors (mean absolute error 4.24 for its best model) on Amazon reviews, with matches judged by
an LLM and no quote audit \citep{tang2025qqsum}. Analysts coding user-generated content against a needs
inventory give the human design we follow for labels \citep{timoshenko2019needs}, and quantification learning
corrects counts for classifier error \citep{forman2008quantifying,esuli2022lequa}. Cost-of-Pass prices the
expected dollars per correct answer \citep{erol2025costofpass}; HAL plots accuracy against cost and finds
that higher reasoning effort lowered accuracy in most runs \citep{kapoor2025hal}; \citet{kapoor2024agents}
argue for cost-controlled evaluation; agents unaware of their budget stop improving as it grows
\citep{liu2025bats}; and SlimSearcher trains agents to make fewer calls at equal accuracy
\citep{xie2026slimsearcher}. These accounts price model tokens, tool calls or API dollars. None prices media
extraction, which a social-media agent pays before it can read speech or on-screen text.

\section{The ReadProof harness}\label{sec:harness}

\begin{figure}[t]
\centering
\rpfigure{fig_harness}
\caption{The ReadProof harness. Every request passes the policy gate; every hop of a redirect is gated; a
read reaches the extractors only when the wall detector says \emph{served}, and otherwise leaves as a typed
\texttt{not\_served} cause. Violet marks ReadProof components, red marks walls, and dashed lines are writes
to the append-only log, which records every gate decision, request, wall verdict, extraction, verification,
model call and budget change.}
\label{fig:harness}
\end{figure}

Figure~\ref{fig:harness} shows the harness. Modules exchange only the typed records of
\texttt{readproof/types.py} through the protocols of \texttt{readproof/interfaces.py}, so each component can
be replaced and tested alone. Three invariants hold throughout. \emph{A wall never reaches a model as page
text:} a read returns records only when a wall verdict says the post was served. \emph{Every record is
content-addressed:} it names the SHA-256 of the snapshot it was extracted from. \emph{Every decision is a log
line:} the trajectory log is append-only and sufficient to recompute every compliance figure we report.

\subsection{Access profiles are data}\label{sec:profiles}
An access profile is a frozen record (\texttt{Profile}) that states whether robots.txt and Content-Signal
bind, whether the read was initiated by a user, whether a headless browser and official-player media are
allowed, the declared user agent, and the retry policy (at most one retry, after a 2-second back-off).
Table~\ref{tab:profiles} lists the three profiles. P0 obeys robots.txt for the harness's declared product
token, or the \texttt{*} group when the file does not name it, with RFC~9309's matching: if no group matches
and there is no \texttt{*} group, ``no rules apply'' \citep{rfc9309}; an unavailable file (4xx) permits access
and an unreachable one is treated as complete disallow, as the RFC specifies. P1 covers a single fetch of a
link that a user supplied. It evaluates and logs robots.txt without treating it as binding, the position
RFC~9309's scope to crawlers allows and the one operators document for their user-triggered fetchers
\citep{openai2026crawlers,tollbit2026googleagent}. We never describe P1 as robots.txt-respecting. P2 covers
content that a person captured or uploaded, so no request is sent. Every result in this paper names its
profile and its network origin.

\subsection{Eight rules, each pinned by a test}\label{sec:rules}
Table~\ref{tab:rules} lists the rules every profile shares. They encode one principle, \emph{no
circumvention, declared identity}: the harness reads only what a platform serves to an honestly named client
that holds no session, and it stops at the first refusal. Each rule is pinned by an offline unit test against
recorded fixtures. A fake transport asserts that every request carries the declared user agent and none
carries a \texttt{Cookie} header; scripted responses assert that a 429 is retried exactly once after the
back-off while a 403, a 412 or a challenge page is never retried; a stub resolver that returns a private
address asserts a refusal before any connection; and a scan of the source tree asserts that no code computes
a platform's request-signature parameters. A reader can therefore check the compliance statement of
Appendix~\ref{app:compliance} by running the test suite rather than by trusting this paper.

\subsection{Policy gate and canonicalizer}
The policy gate decides every request before it is sent and returns a \texttt{GateDecision}: the profile,
whether the request is allowed and why (\texttt{allowed}, \texttt{robots\_disallow}, \texttt{content\_signal},
\texttt{profile}, \texttt{private\_address}, \texttt{scheme}), the robots.txt group and rule that matched,
whether that rule was binding, and the parsed Content-Signal. robots.txt is cached per origin for 24 hours.
A refusal returns \wt{not\_served\{policy\}} without sending a request.

People rarely paste canonical URLs. They paste app share text with a URL inside (\zh{复制打开抖音，看看……}),
short links, links with or without a share token, and alternate domains. The canonicalizer extracts the
first URL from share text, then expands a short link (\texttt{v.douyin.com}, \texttt{xhslink.com},
\texttt{b23.tv}, \texttt{vm.tiktok.com}, \texttt{t.co}, \texttt{youtu.be}) one hop at a time with
\texttt{HEAD} (falling back to \texttt{GET}), never letting the client follow redirects, gating every hop, and
stopping as soon as a platform parser recognizes the target. An unknown short code that redirects to the home
page is typed \wt{soft\_404}, not \wt{deleted}: short codes are case-sensitive, and in the author's logs a
Douyin short code with one letter in the wrong case redirected to the home page exactly as a deleted post
does. Where a share form is disallowed and a canonical form is
not, the canonicalizer rewrites the URL without fetching the disallowed hop: Toutiao's robots.txt disallows
\texttt{/group/} and \texttt{/item/} but not \texttt{/article/} \citep{robots2026toutiao}, so a
\texttt{/group/<id>} link is read as \texttt{/article/<id>/}.

\subsection{Readers and the official-player principle}
Each platform module declares, without network access, how to parse a URL into a post reference, which link
forms exist, and where its oEmbed endpoint and official embed player are. Readers run cheapest first:
oEmbed, the public page, the official embed player, then a headless browser. Every fetch is judged by the wall
detector, and the first served reader supplies records; every wall met on the way is recorded with its
evidence. When a platform serves a post only through its own embed player, ReadProof loads that player in a
fresh browser context and keeps only the media that the player itself requests. The player may compute
whatever request parameters it computes in its own page; ReadProof never computes them (rule~3). The browser
reader asks the gate before navigating and logs every request it observes.

\subsection{Wall detector and typed \texttt{not\_served}}
The wall detector maps a fetch to a \texttt{WallVerdict}: \emph{served} or one of fourteen wall types, with
the evidence that decided it (status, final URL, bytes, visible characters, signature). Platform rules run
first, then generic ones: 429 is \wt{rate\_limited}; 404 or 410 is \wt{deleted}; 401 or a redirect to a login
path is \wt{login}; a redirect to the site root or a generic listing is \wt{soft\_404}; Cloudflare, Akamai,
Tencent and ByteDance challenge markers are \wt{challenge}; a 200 response with fewer than 40 visible
characters and no title is \wt{empty}; and a transport failure is \wt{network}. The platform signatures,
from Douyin's verification page to WeChat's \zh{环境异常} notice, are listed in
Appendix~\ref{app:walls}. The types fall into three states of knowledge, which an abstention reports:
\emph{gone} (\wt{deleted}, \wt{self\_visible}); \emph{not served to this client} (\wt{policy},
\wt{challenge}, \wt{login}, \wt{token}, \wt{app\_only}, \wt{region}, \wt{rate\_limited}, \wt{unsupported});
and \emph{unknown} (\wt{soft\_404}, \wt{empty}, \wt{network}, \wt{unknown}). Saying ``the post does not
exist'' when it was merely not served is a fabrication of its own.

\subsection{Channels, extraction and the evidence store}
Evidence on social media sits in channels, and each channel has its own locator (Table~\ref{tab:channels}).
Extraction runs locally where possible: speech with \texttt{whisper.cpp} \citep{radford2022whisper}; on-screen
and image text with Apple's Vision text recognizer, falling back to Tesseract, on frames chosen by
\texttt{ffmpeg} scene detection plus uniform sampling and de-duplicated by perceptual hash; frame and image
descriptions with an optional vision-language model. Comments are read only when the public page itself
serves them. Every body fetched is stored under its SHA-256, and every record names the snapshot it came
from, the extractor and the fetch time. A record's identifier hashes its post, channel, locator and text, so
re-extracting the same text at the same place yields the same identifier and citations stay valid across
runs. Media is deleted after extraction unless a run explicitly keeps it.

\subsection{Verification, budget, log and interface}
A citation is a record identifier and a quote. The verifier normalizes both texts with a fixed Unicode and
whitespace normalization and accepts the citation only if the quote is a substring of the record and is long
enough to be substantial; the \texttt{verified} flag is set by this code, never by a model. Every tool is
priced in US dollars and seconds by a budget tracker, which refuses work past a cap. The trajectory log is
JSONL with one line per gate decision, request, wall verdict, extraction, verification, model call and budget
change; it is append-only, synchronized to disk on close, and replayable. The compliance checks of
Table~\ref{tab:compliance} are computed from it alone. Agents call the harness through the Model Context
Protocol \citep{mcp2026spec} with six tools: \texttt{read}, \texttt{search\_records}, \texttt{verify},
\texttt{label\_posts}, \texttt{count} and \texttt{budget}. A wall comes back as a typed object, never as text,
so any agent, whether a ReAct loop, a deep-research framework or a commercial model with tool use, gets the
same reading, logging and cost accounting.

\paragraph{Track A: access across link forms.}
We sample \NAPosts{} public posts on nine platforms (Douyin, Xiaohongshu and RedNote, Bilibili, YouTube,
TikTok, Weibo, Toutiao, X and WeChat), stratified by whether a web search engine indexes the post or the
post was found by browsing the platform by hand, so that discovery bias can be measured. For each post the
link-form generator emits the forms people actually paste (Appendix~\ref{app:forms}): desktop and mobile
URLs, app share text, short links taken from the platform's share button, Xiaohongshu links with the share
token kept, stripped or altered, alternate domains and paths, and Toutiao's share and article forms. A
person records, on a dated device, what the official app shows for each form: whether the post is served,
its wall type if not, and a reference fingerprint (title or caption) used to decide whether a system's
payload contains the post. \NAControls{} control forms have known walls: deleted posts, posts visible only to
their authors, and short codes with one character's case flipped. The scoring unit is the link form, not the
post, because the same post can open from one form and fail from another.

\paragraph{Track K: planted canaries.}
The author publishes genuine posts on Douyin, Bilibili, YouTube, TikTok, RedNote and X. Each carries a
distinct random code in exactly one channel: spoken only, on screen only, in the caption only, in a pinned
comment only, or in a carousel image only. The question is always ``what code does this post contain?''. A
correct code proves that the system read that channel on that platform, without access to its logs; a
different code is a fabrication; ``not found'' is an abstention. Codes differ across posts, so no code can be
known in advance. After a first round, the author deletes some posts or makes them visible only to
themselves, which yields walls whose state is known exactly. The panel extends the planted codes of the
robots.txt study of ten assistants \citep{lopezfonseca2026robots} to third-party platforms that cannot be
instrumented from outside, and it is the one slice whose media can be released in full, because the author
holds the rights.

\paragraph{Track B: channel-located evidence.}
Each of the \NBQuestions{} questions (\NBZhShare{} in Chinese) is answerable from exactly one channel of one
third-party post: \ch{speech}, \ch{on\_screen}, \ch{frame}, \ch{image\_text}, \ch{caption} or \ch{comment}.
An item holds the question, a short answer, the gold channel and locator, and a verbatim gold quote. Gold
comes from the agreement of two independent extractors: \texttt{whisper.cpp} and an omni model for speech,
and Vision OCR and a vision-language model for on-screen and image text. The gold quote must appear, after
normalization, in both extractors' outputs at overlapping locators, and the answer must appear in no other
channel of the post; disagreements go to the author. Two filters keep the items honest. A
\emph{closed-book} filter drops any question that a strong model answers from the question and the URL
string alone, the lesson of benchmarks that turn out to be answerable without their videos
\citep{lee2026vragbench}; an \emph{answerability} filter drops any question that the same model fails when
given only the gold record. Both follow BrowseComp's rule that answers be hard to find but easy to verify
\citep{wei2025browsecomp}. The author audits \NAudit{} items by hand.

\paragraph{Track C: counting (pilot).}
Each of the \NCSets{} sets holds posts on one topic, such as a product complaint, a destination or a policy
claim. Following Key Point Analysis \citep{friedman2021kpa} and analyst-coded customer-needs studies
\citep{timoshenko2019needs}, each set has an inventory of aspects, and two annotators label every post for
every aspect (yes, no or unclear), with an evidence span and its channel; we report Cohen's $\kappa$
(\NCKappa{}). The gold count is computed from the labels, as QQSUM derives prevalence from matches on
individual comments \citep{tang2025qqsum}. Questions take the form ``of these $M$ posts, how many say $A$?'',
with one verified quote per counted post.

\paragraph{Release and contamination controls.}
Third-party content is released only as post identifiers, URLs, snapshot hashes, locators and short quotes,
never as media; Track~K media is released in full. Test answers are withheld for a leaderboard, as GAIA
withholds 300 of its 466 answers \citep{mialon2023gaia}. Every file carries a canary GUID, and during
evaluation search results that name the benchmark or contain the GUID are blocked, the control that stopped
answer-key leakage on BrowseComp \citep{anthropic2026evalawareness}; any trajectory that reaches benchmark
material is scored as wrong. Benchmark and canary posts are never read through any service that republishes
what it reads. The frozen track replays stored snapshots offline; the live track lists the links and a
re-probe schedule, so that the decay of access can be published as a curve. Code is released under
Apache-2.0 and annotations under CC~BY~4.0. Appendix~\ref{app:datasheet} is the datasheet
\citep{gebru2021datasheets}.

\section{Read--verify--count}\label{sec:method}

\begin{figure}[t]
\centering
\rpfigure{fig_dataflow}
\caption{Data flow from a question to an answer. Every stage emits a typed record. Walls leave the pipeline
as typed causes and never reach the model as page text; quotes are verified and counts computed in code.
Every arrow writes one line to the trajectory log.}
\label{fig:dataflow}
\end{figure}

Read--verify--count is the method the orchestrator runs (Figure~\ref{fig:dataflow}). It needs no training:
three parts are code and one is a prompted model, and each part can be ablated alone.

\paragraph{M1: typed abstention.}
When a read is not served, the method abstains with the wall type as its cause, and the model never sees the
page. When a read is served but no verified citation supports an answer after one re-ask, it abstains with
cause \texttt{unsupported}. An answer therefore takes one of three forms: a cited answer, an abstention with
a wall cause, or an abstention for lack of support. We evaluate it as selective prediction: the
answer-from-wall rate, abstention precision and recall, and abstention with the correct cause.

\paragraph{M2: extraction routed by a priced budget.}
Extraction dominates the cost of reading video, so the router orders channels by expected value per unit
cost. For a question $q$ and a served post, let $\pi_k(q)$ be the prior probability that channel $k$ holds
supporting evidence and $p_k$ its price for this post (US dollars and seconds, from the media duration and
the budget tracker's rates). The router extracts the next channel in decreasing order of $\pi_k(q)/p_k$,
retrieves within it with character $n$-gram BM25, fuses channels by reciprocal rank
\citep{samuel2025mmmorrf}, and asks the model for a cited answer; it stops as soon as a verified quote supports
the answer or the budget is spent. By default $\pi$ is uniform, which yields the cost order: caption, title
and served comments, which cost nothing beyond the page; then on-screen text from keyframes; then speech;
then frame descriptions. A variant predicts $\pi(q)$ with one short model call. The budget is priced in
dollars and seconds, not in calls, because tools differ in price and a budget that counts calls
\citep{liu2025bats,xie2026slimsearcher} treats a minute of speech recognition like a text search.

\paragraph{M3a: verified-quote citations with one re-ask.}
The model must return each claim with a record identifier and a quote copied from that record. Code checks
every quote. If a quote fails, the model is asked once more, shown which quote failed and the record's
text; if it fails again, the claim is dropped, and an answer left without a verified citation becomes an
abstention with cause \texttt{unsupported}. The rule is enforced in code rather than in the prompt: a prompt
can ask for exact quotes, but only code can refuse an inexact one.

\paragraph{M3b: counting in code.}
For a set of posts and an aspect $A$, a worker labels each served post separately (yes, no or unclear) with a
quote, which is verified as in M3a; a label whose quote fails twice becomes \emph{unclear}. Code then counts
$\hat N = |\{\text{yes}\}|$ among the $M$ served posts and reports the $K$ posts that were not served by
cause, so the answer reads ``$\hat N$ of $M$ served posts ($K$ not served: \dots)'', with one verified quote per
counted post. Because labels contain errors, we also report the adjusted classify-and-count estimate
\citep{forman2008quantifying}
\begin{equation}\label{eq:acc}
  N_{\mathrm{adj}} \;=\; \min\!\Bigl(M,\; \max\!\Bigl(0,\; \frac{\hat N - \alpha M}{1-\alpha-\beta}\Bigr)\Bigr),
\end{equation}
where $\alpha$ and $\beta$ are the labeller's false-positive and false-negative rates on a calibration set of
\NCalib{} posts labelled by two people. A 95\% interval comes from a bootstrap that resamples both the posts
and the calibration items. When $1-\alpha-\beta < 0.1$ the labeller is close to chance, and we report $\hat N$
with a flag instead. Labelling each post separately and counting in code follows the centrally coordinated
pattern that contains error amplification \citep{kim2025scaling}, and addresses the failure that in long
contexts aggregation, not classification, is the bottleneck \citep{bertsch2025oolong}.

\paragraph{Backbone.}
All model-using systems share one open-weights backbone per run, \nolinkurl{google/gemma-4-31b-it} through
OpenRouter's free tier \citep{openrouter2026gemma4}, with a 262{,}144-token context. Decoding settings are
fixed per run and logged, and responses are cached by request hash so that a replay is exact. Prompts are in
Appendix~\ref{app:prompts}.

\paragraph{Profiles, origins and arms.}
Headline results use P1 from a residential origin (\ParamResidential{}); ablations use P0 and a datacenter
origin (\ParamDatacenter{}). Every request is labelled with its origin. In the \emph{live arm}, links are
fetched on \ParamLiveDays{} days from the fixed origin, with requests to any host spaced at least two seconds
apart; we report the mean over \ParamRuns{} runs and the day-to-day spread. In the \emph{frozen replay arm},
every system re-runs on the payloads it fetched, served from the evidence store, and on Track~B every
model-using system also receives the same served records, which isolates reasoning, verification and routing
from acquisition. Collection dates: \ParamCollection{}.

\paragraph{Metrics.}
For a system $S$ and a set of link forms $F$, \emph{coverage} is
\begin{equation}\label{eq:cov}
  \mathrm{cov}(S,F) \;=\; \frac{1}{|F|}\sum_{f\in F}\mathbf{1}\bigl[\,\mathrm{fp}(f) \subseteq \mathrm{text}_S(f)\,\bigr],
\end{equation}
where $\mathrm{fp}(f)$ is the reference fingerprint of the post behind $f$ and $\mathrm{text}_S(f)$ the
visible text of the payload $S$ received. A read whose payload fails that check is a wall for $S$, whatever
status code it carried. The \emph{answer-from-wall rate} is the share of walls after which $S$ still answers instead of
abstaining. \emph{Abstention precision} is the share of abstentions that follow a wall, and \emph{abstention
recall} the share of walls followed by an abstention. \emph{Wall-type accuracy} compares the predicted type
with the gold type on control forms; we also report macro-F1 over types. On Track~B, \emph{accuracy} is
exact match after normalization, reported per gold channel; \emph{locator accuracy} counts a locator as
correct if a speech span overlaps the gold span with temporal IoU of at least 0.5, a frame timestamp is
within \ParamFrameTol{} seconds of the gold one, or an image index, field or comment rank matches. On
Track~K, \emph{exact-code accuracy} is exact string match with the planted code, and the \emph{fabrication
rate} is the share of answers that give a different code. \emph{Quote validity} is the share of citations
whose quote is a substring, after normalization, of the stored record it names; for baselines, of the visible
text of the payload they received. On Track~C we report the absolute and relative error of the count,
post-set F1, and \emph{interval coverage}, the share of sets whose 95\% interval contains the gold count.
\emph{Cost per correct answer} divides the total cost of a run by its number of correct answers and is split
into media extraction and model tokens, in dollars and in seconds. Local extractors cost measured seconds and
no dollars; model calls are priced at the list price of the paid endpoint of the same model
(\ParamTokenPrice{}), so that costs do not depend on free-tier quotas. The \emph{compliance log checks}
count requests without the declared identity, requests carrying cookies, retries after a refusal, and fetches
of robots-disallowed URLs, all of which should be zero for ReadProof under P0.

\paragraph{Statistics.}
Every comparison between two systems is paired on the same items and carries a 95\% percentile interval from
10{,}000 bootstrap resamples. On Track~A we resample posts rather than forms, because the forms of one post
are correlated; on Track~C we resample sets and calibration items. We claim a difference only when its
interval excludes zero, and we compare harnesses only on the same backbone and budget.

\paragraph{Hypotheses.}
We state before running the experiments what each would falsify.
\textbf{H1}: most end-to-end failures of the baselines occur at acquisition, detection or extraction rather
than grounding; falsified if at least half occur at grounding. \textbf{H2}: the baselines answer from a
substantial share of walls, and typed abstention brings the answer-from-wall rate near zero at a small cost
in answered questions; falsified if the baselines already rarely answer from walls, or if abstention costs
more correct answers than it removes wrong ones. \textbf{H3}: accuracy is lowest when the evidence exists only
on screen or in carousel image text; falsified if no channel differs beyond the intervals. \textbf{H4}:
code counting with verified quotes has lower count error than counts written in prose, with interval coverage
near 95\%; falsified if the error is not lower or coverage falls below 85\%. \textbf{H5}: routed extraction
matches extracting every channel at lower cost; falsified if extracting everything dominates on the
accuracy--cost plane. \textbf{H6} is descriptive: under P0, a strict reading of robots.txt excludes a
measurable share of the benchmark.

\section{Analysis}\label{sec:analysis}

\paragraph{The honesty penalty.}
Table~\ref{tab:honesty} reports, per platform, ReadProof's coverage under P0 and P1, their difference (the
honesty penalty), the share of link forms that a strict reading of robots.txt excludes, and the effect of
network origin. The static part needs no experiment. Under RFC~9309, a bot that a robots.txt file does not
name obeys the \texttt{*} group, and if there is none, no rules apply \citep{rfc9309}. Read that way, the
files fetched on 21 November 2026 exclude an honest new bot from Xiaohongshu and RedNote note pages, Weibo
posts and WeChat articles altogether: xiaohongshu.com and mp.weixin.qq.com disallow every path for
\texttt{*}, rednote.com opens its note paths only to a named search crawler, and weibo.com disallows every
path for \texttt{*} while declaring \texttt{ai-input=yes} in its Content-Signal
\citep{robots2026xiaohongshu,robots2026rednote,robots2026weixin,robots2026weibo}. Douyin's file has no
\texttt{*} group, so no rules apply to an unnamed bot, yet its share pages answer every client with a
verification page \citep{robots2026douyin}: ``allowed'' and ``served'' are separate measurements. TikTok's
file disallows every path for self-named AI agents, among them ChatGPT-User and Claude-User, while leaving
video pages open to \texttt{*} \citep{robots2026tiktok}, so a bot that declares itself as an AI agent loses
access that an anonymous one keeps. The penalty is therefore not one number but a property of each platform's
file and of how a bot names itself. Overall, the strict reading excludes \ResHeadStrictExcluded{} of the
benchmark, and the measured penalty is \ResHeadPenalty{}. \pending{Results text.}

\paragraph{Network origin.}
Refusals follow the outgoing address as well as the request. Bilibili's player answers code $-412$ to a
refused address (Appendix~\ref{app:walls}), and in the author's logs Xiaohongshu refused some addresses while
serving the same note to others, so the same link can be served at home and refused from a cloud region. We fix the origin per arm and label every request with
it; the last column of Table~\ref{tab:honesty} and the datacenter row of Table~\ref{tab:ablation} measure the
effect (\ResHeadOrigin{} overall). Rule~4 forbids the obvious remedy, moving to another address after a
refusal. \pending{Results text.}

\section{Limitations and ethics}\label{sec:limits}

\paragraph{Compliance scope.}
The claim we make is \emph{no circumvention, declared identity}, enforced by the eight rules and checkable by
running the tests. We do not claim that P1 respects robots.txt: it evaluates and logs robots.txt on every
request, binds it only under P0, and reports the difference as a measured result. A strict reading of
robots.txt excludes Xiaohongshu and RedNote, Weibo and WeChat articles for an honest bot that the files do not
name (Section~\ref{sec:analysis}); results on those platforms are P1 results and are labelled as such. We do
not measure what circumvention would gain, because we never run it, and we compare login- or signature-based
tools \citep{nanmicoder2026mediacrawler,xpzouying2026xhsmcp,evil0ctal2026douyinapi} only from their
documentation. Legal analyses in the United States and China concentrate liability on deception and on
evading technical measures; China's 2025 Anti-Unfair Competition Law, for instance, bars obtaining another
operator's data by evading or breaking technical management measures \citep{prc2025aucl}, and its network-data
regulation requires automated collection not to interfere with services \citep{prc2024networkdata}. The rules
exclude both by construction. This paragraph describes the design; it is not legal advice.

\paragraph{Data release and privacy.}
Third-party content is released as identifiers, URLs, hashes, locators and short quotes, never as media, and
items are scrubbed of personal information before release. We do not release commenter identities or user
profiles, and we use no data from LinkDigest's customers. Posts whose authors ask for removal are dropped from
the next release. The canary posts are the author's own genuine posts, published under the platforms' rules;
their codes are random strings shown openly, and the posts contain no misleading content.

\paragraph{Validity.}
Walls change over time and by address, so Track~A is a dated snapshot from fixed origins; the live track
publishes the decay. Gold for Track~A is what one person saw in the official app on one device. Track~B gold
depends on two extractors agreeing, which can drop hard items; the author's audit estimates how often. Track~C
is a pilot, and its intervals assume the calibration set represents the labeller's errors. Results use one
open-weights backbone; harness comparisons hold the backbone fixed, but absolute numbers will move with the
model. The benchmark covers Chinese and English and nine platforms, and its share of each is a design choice.

\paragraph{Competing interest.}
The author operates LinkDigest, a commercial service that reads social-media links. The harness and benchmark
are independent of it, and no LinkDigest production route is used in any reported result.

\section{Conclusion}\label{sec:conclusion}

On social media the hard part of agentic search is not reasoning but establishing what was read, from which
channel, under which rules and at what cost. ReadProof turns each of those into something a log can show: a
typed wall instead of a block page, a record with a channel, a locator and a snapshot hash instead of a
summary, a quote checked by code instead of a citation taken on trust, and a count computed rather than
written. Because the harness never works around a platform's defences, every wall it meets becomes a
labelled data point, and reporting results by access profile turns ``is it compliant?'' into ``what does each
level of honesty cost?''. Acquisition and extraction gains should not shrink as models grow, because a
larger model still cannot read a verification page; with the released harness, that claim can be tested
rather than assumed.

\section{Prompts}\label{app:prompts}
All prompts ask for JSON; code parses and verifies the output.

\paragraph{Answer (read--verify--count).}
\begin{quote}\small\ttfamily\raggedright
You answer a question about one social-media post using only the records below. Each record has an id, a
channel and a locator. Answer briefly. Support every claim with one record id and a quote copied from that
record exactly. If the records do not contain the answer, reply NOT\_FOUND.\\
Return \{"answer": string or "NOT\_FOUND", "citations": [\{"record\_id": string, "quote": string\}]\}.
\end{quote}

\paragraph{Re-ask after a failed quote.}
\begin{quote}\small\ttfamily\raggedright
Your quote "<quote>" does not occur in record <record\_id>. Its text is: <text>. Copy the supporting words
exactly, or reply NOT\_FOUND.
\end{quote}

\paragraph{Per-post label (Track C).}
\begin{quote}\small\ttfamily\raggedright
Does this post say <aspect>? Answer yes, no or unclear, and copy one exact quote from the records that shows
it. Return \{"label": "yes" | "no" | "unclear", "record\_id": string, "quote": string\}.
\end{quote}

\paragraph{Canary question (Track K).}
\begin{quote}\small\ttfamily\raggedright
What code does this post contain? Reply with the code exactly as it appears, or NOT\_FOUND.
\end{quote}

\paragraph{Baselines.}
\begin{quote}\small\ttfamily\raggedright
Here is the text of the page at <url>: <text>. Answer the question. If the page does not contain the answer,
reply NOT\_FOUND.
\end{quote}
\sys{closed\_book} receives the same prompt with the page text replaced by ``(not available)''.

\paragraph{Filters (Track B).}
The closed-book filter asks the question with the URL string only; the answerability filter asks it with the
gold record only, using the answer prompt above.
